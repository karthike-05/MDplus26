Simulate inbound reply

Posts to /webhook/sms-inbound — the same path Twilio hits. In live mode the patient messages your WhatsApp number instead. The reply is classified by the LLM, so free-form text ("went yesterday, thanks") works, not just YES/NO.

How a case starts

The loop is DB-driven, not created from this dashboard:
  1. Loop A (poller.py) picks up a confirm_consent action from referral_actions (assigned_component='twilio'), creates the case, and sends the consent message.
  2. The patient replies → this webhook advances the case (stage) and writes consent back.
  3. Loop B (scheduler.py) fires the reminder, verification, nudge, and escalation on the service-date schedule.
To seed a demo case, insert a synthetic referral + confirm_consent action per docs/…/e-integration-checklist.md.
